# Écartéo manual acceptance, 17 November 2026

The three-role audit journey passed on hosted staging. The production owner could sign in on [app.ecarteo.fr](https://app.ecarteo.fr/login), refresh the dashboard, and open requests and team management. A deliberate refresh issued one document navigation; an unsolicited reload loop was not observed. The fixes below were tested on a local release build. This QA run did not deploy or modify customer audits in production.

**Release checks.** All 233 unit and integration tests passed against a fresh disposable PostgreSQL database after migration and tenant-isolation checks. The production build, TypeScript, lint and formatting passed. Of 25 Chromium release cases, 24 applied and passed: 20 on the first run and four on retry with fresh local accounts after the intended ten-login rate limit returned 429. The unconfigured-provider case was intentionally skipped because Supabase was connected. Five additional local inbox/onboarding cases passed. A development-server login navigation was interrupted during testing; its equivalent passed on the release build and the production-owner smoke check.

**Scope limits.** The public UI has no privacy or terms link configured; Intertrad needs to provide the approved, published URLs. Real production SMTP delivery, live Stripe transactions, physical-device behavior and peak-load capacity were not verified. Chromium and WebKit mobile checks used viewport/touch emulation. Results from staging or local Supabase do not certify production email, payments or mobile hardware.
