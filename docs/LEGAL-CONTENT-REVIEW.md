## Manual request and retention review

The person monitoring `admin-dev@ecarteo.fr` routes each support/privacy request to an authorized quality administrator. Use the restricted privacy-case process in [OPERATIONS.md](OPERATIONS.md), and keep case details out of public logs and source control.

1. Identify the account, organisation, mission and request. Verify identity and authority using only information necessary for that case; never ask for passwords.
2. Identify which organisation controls the relevant mission data and coordinate the request with it where required. Check the service agreement and any legal preservation duty before changing records.
3. Inventory relevant database records, evidence objects, exports and backup copies. Record the continuing purpose, access restrictions and the action for each category; do not use an unspecified indefinite retention period as the default.
4. Perform only the reviewed action appropriate to that case. The current privacy tooling records/reviews/exports; it is not a blanket automated deletion system. Published-report integrity and dated supplements need coordinated treatment when a lawful erasure request applies.
5. Record the decision, responsible person, follow-up date and response. If a backup must be retained, restrict it and record how erased data will be handled on any subsequent restore. Record actual off-site retention and expiry when storage is configured.

Review account/organisation records at closure, audit records at the end of the agreed follow-up, operational logs for their security purpose, and support/privacy cases after resolution. Specific periods, holds and customer data-protection instructions remain part of the real service agreement and operations record; the public pages make no automatic-erasure promise.
